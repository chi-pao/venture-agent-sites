# AI事業開発エージェントの管理

## Windowsでの利用

`update-and-start.cmd`を既存の`C:\AI事業開発`に置く。既存アプリをCtrl+Cで終了してからダブルクリックする。既存のPython環境・Streamlit・Ollamaを使う。追加インストールや課金設定は行わない。

起動時にrelease.jsonを読み、指定されたGitHubコミットのコードを取得する。SHA-256とPython構文を確認してから、SQLiteの整合性あるバックアップと旧コードの退避を行い、コードを入れ替える。取得・検査が失敗したら既存の管理版を使用する。初回失敗時は既存ファイルを変更しない。ポート8501使用中は更新しない。

更新を入れた直後は、起動前に新しい版の画面を一度だけ裏で表示して確認する（DBの複製を使い、APIキー等の`VENTURE_`環境変数は渡さない）。確認で失敗した場合や、更新直後60秒以内に異常終了した場合は、自動で前の版に戻して起動し、その版は`code/failed_updates.json`に記録して再導入しない。確認を実行できない環境（Streamlitの検査機能がない・時間切れ）では新しい版を「未確認」と表示して起動する。DBは自動で巻き戻さない。

この自動復旧は2026-10-31版の起動プログラムから。古い`update-and-start.cmd`は古い起動プログラムを固定で取得するため、GitHubの`agent/update-and-start.cmd`で一度だけ置き換える。

手動で旧コードへ戻す場合は黒い画面で終了後、同じフォルダーで`update-and-start.cmd --rollback`を実行する。DBは自動で巻き戻さない。DB構造を変える将来の更新は、後方互換性と復元手順を確認してからリリースする。

## PC内の構成

|場所|用途|
|---|---|
|code/|本体コード・旧版・導入版情報・起動制御|
|venture_agent_integrated.db|既存の事業・設定・履歴。移動しない|
|venture_outputs/projects/<事業ID>/job_<番号>/|今後の成果物。事業IDは事業名のSHA-256先頭16桁|
|venture_outputs/job_<番号>/|以前の成果物。移動せず参照を維持|
|venture_agent_autonomous/|既存の運転・探索・資格情報管理。移動しない|
|backups/<日時>/|更新前のDBと旧コード。勝手に削除しない|

同じ事業内の計画・HTML・検査記録はDBで種類を管理する。中止・保留の製品は通常の確認一覧から外し、表示チェックで参照できる。

## 開発とリリース

GitHubのagent/には公開できるコードと案内だけを置く。DB・ログ・成果物・APIキー・SNS資格情報・PCのバックアップをコミットしない。PCデータをアップロードする機能はない。既存のCloudflare静的サイト配信と旅行APIの開発は独立して継続する。

コード修正後は、更新・保存・承認・プレビュー等の回帰テストを行い、コードをコミットする。その確定コミットURLとハッシュをrelease.jsonに設定して最後に更新する。公開アプリの変更とSNS発信は、製品ごとの利用者のOKを必要とする。プログラム更新だけで製品を承認しない。

今の本体は単一Pythonファイルを維持している。今後複数ファイルが必要になった場合は、リリース単位の検証・一括切替ができる更新方式へ拡張してから追加する。フォルダーを作っただけで複数ファイルの自動配布に対応済みとはしない。

## 制限

PCの電源・ネット接続・Python・Streamlit・Ollamaが必要。Windows実機での初回起動確認は必要。自動修正による製品の実用性・収益性は保証しない。外部API・サーバー機能は接続と実装が済むまで未完成として扱う。
