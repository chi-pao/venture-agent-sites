# Department pipeline — development version

This replaces the production-improvement scheduler with persistent handoffs, using the existing real engines. It does not establish universal app-generation quality. `release.json` is intentionally unchanged until real proof passes.

| Department | Real engine | Output / return path |
| --- | --- | --- |
| Proposal | `ensure_product_spec` | Audience, workflow, must-have functions, acceptance cases, dependencies |
| Research | `ensure_competitive_brief` | Official feature sources and actual desktop/mobile references; unavailable research remains a gap |
| Design | `ensure_product_blueprint`, `ensure_implementation_plan` | Screen hierarchy, core journeys, feature/data/error contracts and concrete tests |
| Development | `build` | Exact candidate source plus preliminary validation; failing candidates are retained for repair |
| Verification | `automated_product_qa` | Real browser workflow and visual comparisons, bound to the candidate and requirement hashes |
| Operations | Existing owner-approval and publication checks | Approval wait; this manager does not publish, approve, post, or create accounts |

## Coordination

`department_manager.py` owns state and immutable JSON receipts. `department_adapter.py` supplies real app engines. `bundle_departments.py` embeds both into the single program used by the current Windows checksum-verified updater. Run `python agent/bundle_departments.py --check` in CI to catch a stale bundle.

Receipts live under `venture_outputs/departments/<product hash>/<requirement hash>/<department>/`. The database stores current task states and feedback. Reopening the program revalidates receipt bytes before reuse. A requirements change starts a new scope; old receipts remain on disk. A verifier/environment failure reuses the exact development candidate. A design failure returns to design, then rebuilds and rechecks. An unavailable market/competitor source does not stop independent prototyping; owner review still requires research evidence. Repeated diagnostic signatures are remembered independently of temporary feedback.

The coordinator asks the independent QA planner to derive browser cases from the requirements and visible screen, rather than reusing the renderer's own expected-value compiler. This avoids treating agreement with a template as proof that all requested workflows exist.

Different models can be assigned through configuration `department_models` (`proposal`, `research`, `design`, `development`, `verification`); unspecified roles retain existing models. This is role separation, not a claim that six different models or six simultaneous processes are running. CPU/GPU work is sequential to avoid exhausting local resources. Configuration/model changes invalidate affected receipts. Model weights are not trained by these records.

The dashboard shows six department states and the current return instructions beside the app preview. Department completion means only its contract passed. No preliminary screen check can override the existing final functional, visual or owner-approval checks.

## Validation and limits

The first real-model department runs failed: independent QA planning timed out
when generating five base scenarios or several feature cases together. The new
`qa_checkpoint_planner.py` generates one scenario/case at a time from compact
actual controls and result selectors. It saves each validated unit with an input
hash, retains successful units across timeouts, independently audits each pair
of requirement tests, and runs the unchanged final plan/browser/visual gates.
It does not reuse the renderer's expected-value compiler. Research transport
errors also no longer invalidate provisional offline design just because the
error text changes. The live workflow resumes the latest real checkpoint
artifact instead of regenerating completed design and source from zero.

These changes have resumption, cache invalidation, prompt-budget and rejection
unit tests. Real model success is still a separate required result.

`test_department_manager.py` exercises restart/resume, targeted returns, independent research gaps, changed requirements/configuration, receipt tampering, stop requests and repeated failure memory. `test_department_adapter.py` verifies wiring and approval protection with substituted engines; these tests are not real model evidence.

`tests/department_live_smoke.py` runs real models and Chromium through this coordinator for attendance, workday and a new returns workflow. The workflow fails if any product cannot reach the unchanged quality bar. Its artifacts keep the source, model results, task receipts and browser reports. Three successful examples would establish only those tested cases, not every future business or commercial viability. Low design/function quality requires improving the responsible engine and testing again; adding departments alone does not guarantee quality.

The saved workday specification also contained instruction text and unrequested collaborative-editing criteria. The proposal handler now detects these known contamination patterns and reconstructs acceptance conditions one original must-have requirement at a time, with persisted partial results. User-authored contracts are not silently overwritten. The general spec prompt no longer instructs every product to add search or collaboration. Original must-have/workflow/dependency fields remain intact; replacement acceptance conditions are still hypotheses until exercised by independent browser tests.

The 4aed971 real replay exposed two additional model-format failures: the workday acceptance repair omitted required fields, and attendance QA emitted invalid acceptance indices. The next revision constrains these short responses with JSON Schema, bounds retries without increasing the output budget, persists rejected responses, and records proposal failures as resumable state rather than crashing the proof run. HTTP 400 schema transport fallback retains the same small token budget. Full unit/browser success still does not establish real-model product quality.

Return-workflow evidence showed repeated 120-second code-repair timeouts after a QA-planning failure, even though no product defect had been found. The adapter now retains the intact same-scope preliminary candidate when there is no development/design feedback. Actual feature or visual feedback still rebuilds it. QA consumes the validated same-scope design/engineering handoff instead of calling the design models again, but still independently generates tests and executes browser/visual checks. These paths have separate wiring and rejection tests.

The fb55ead real replay failed before browser execution for returns and attendance: the rejected workflow response copied `{index, condition}` objects into integer-only `acceptance`, used a message as a wait duration, and used an operation name as the result selector. On HTTP 400 fallback, `_schema_in_prompt:false` had removed the output schema from both the transport and the prompt. JSON-mode fallback now explicitly includes the schema; the planner context uses an index-to-condition map and states numeric IDs, integer wait milliseconds, and real CSS targets. Rejected values remain failures, with actionable field feedback; expectations and semantic/browser/vision gates are not relaxed. The workday replay still hit repeated patch timeouts after specification repair changed scope. Patch timeouts now preserve the old source and enter the existing alternate-generation path within the same cycle, tested with a simulated timeout. Related control tests (54) pass; actual model/browser quality remains unproven. The prior fb55ead full CI passed 130 tests, which is not a real-generation pass.

The ced4cd5 replay progressed past malformed acceptance IDs, but returns/attendance still emitted only `text_contains` assertions (e.g. the digit `1`), filled a select as a text field, and treated a result element as a checkbox. QA correctly rejected these plans; no browser-quality pass was claimed. Workflow/variant/feature response schemas now require an explicit `exact_check` with `op:text_equals`, a real result selector and the independently calculated full expected string. The parser merges that assertion into standard browser checks without manufacturing a value or converting contains to equals. Exact inventory matches reject invalid select/checkbox actions before browser execution. Two additional control tests cover partial-only rejection and wrong control operations. Related local tests: 56 passed. This is a planner fix pending actual model evidence, not completed product quality. Existing workday acceptance repairs also contain questionable units/expected calculations, so their semantic correctness remains an open issue and must not be treated as verified merely because the response shape passed.

The same preserved workday contract had examples whose units/calculations were inconsistent and whose multi-operation acceptance text was cut at the former 120-character limit. Repaired acceptance now has a separate, checkpointed semantic audit of the original must-have, action coverage, units and independently recomputed expected result. A rejected condition is deleted individually and its audit feedback is forwarded to the next proposal repair; it is never stored as a verified contract. The bounded field limit is 400 characters to avoid cutting multi-step requirements, and older unaudited repairs are migrated through this audit. A regression fixture rejects a 480-minute answer for 09:00–17:00 minus 60 minutes. All 57 related local tests pass. Real semantic auditing remains unproven until the next live replay; browser/visual/reference-quality gates remain unchanged. The ced4cd5 workday replay did get past the repeated patch timeout into independent test planning, then hit the same missing exact-result check as the other two products.

The 90ec01a real replay got returns/attendance through workflow, variant and reload planning, but the model emitted ordinary clicks for CSV/JSON/restore instead of the harness's file operations, and omitted the required mutation/cancellation sequence. Roundtrip planning now requests typed bindings (actual CSV/JSON/restore selectors, CSV values, record-C mutation and final assertions), while a deterministic QA-only compiler emits the real-file download/change/cancel/restore protocol. This is shared test infrastructure, not a replacement app renderer or an inferred business oracle. Existing checks/expected values remain independently generated, and the browser still checks downloaded bytes, actual changed storage and actual restored storage. Existing passing base checkpoints keep the same cache policy; only the changed roundtrip input hash is invalidated. Unit coverage rejects non-mutating bindings and verifies exact file-operation order. The real-Chromium fixture tests for attendance/workday now also use this compiler; model-generation quality remains a separate live CI gate.

Workday's new semantic audit correctly refused inconsistent inputs/calculations, but regeneration did not receive the rejected candidate itself. Proposal repair now includes both the previous candidate and full audit feedback, asks for named values with units, and separates clock times from durations. The auditor is explicitly forbidden from inventing constraints such as requiring planned and actual time to match. A unit test verifies candidate-plus-feedback handoff; it does not claim model arithmetic reliability. Related local control tests: 59 passed. The live replay must still demonstrate semantic repair and real browser/visual quality before any release.

The ffb75a9 replay still returned the old steps/kind envelope for the new backup binding request: the shared operation instructions and full preceding scenario examples conflicted with the new top-level contract. Roundtrip now uses a dedicated instruction block and a literal JSON envelope, and supplies prior input values/final expectations without copying old step envelopes. QA schemas use direct required keys rather than required-only anyOf branches; if the server rejects a schema, a per-part transport receipt now records the actual HTTP 400 reason before the existing strict JSON fallback. Whether this avoids real Ollama schema rejection must be checked in the next artifact, not assumed.

The full fixture CI also exposed a test-only KeyError when the new compiler test read optional rationale from older attendance/workday fixtures. That fixture metadata read is corrected. Both fixture protocols compile locally (8/10 steps); real Chromium execution remains required in CI. Related control tests: 61 passed. Workday's real semantic audit still rejected repeated unit/calculation mismatches; it has not produced a validated repaired contract. No release or completed-product claim is authorized by these control tests.

The 09127eb live replay advanced past backup bindings into invalid-input and feature-case planning. Invalid plans omitted the special corrupt-file operation; the new invalid binding compiler emits restore_invalid itself and requires real invalid field input/submission and unchanged-state checks. It does not invent domain answers. Existing valid workflow/variant/reload parts are preserved.

Full Chromium fixture CI exposed a protocol mismatch: in-page confirmation buttons were accidentally included in the pre-restore mutation when adapting the fixtures. Bindings now distinguish native dialogs from inline confirmation, explicitly identify the inline cancel/confirm buttons, and the browser runner clicks the actual inline cancel while checking storage did not change. Fixture adaptation separates mutation before the first restore from confirmation after the last restore. Both attendance/workday Chromium tests exercise the new protocol; CI must pass before claiming correctness. Local control tests: 63 passed.
