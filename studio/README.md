# 事業スタジオ

AI が「お金になりそうなアプリ」を考え、勝てるかを調べ、**ある程度の品質のアプリになるまで自動で作ります**。
のぼるさんがするのは、最後に完成品を見て決めることだけです。

- **続ける** … 事業として独立させて進める
- **ブラッシュアップ** … 直す点を伝えて、もう一度作り直す
- **やめる** … 理由は次の企画に生かす

あわせて、今ある SNS で発信する部門と、楽天アフィリエイトで物を売る部門もあります。
以前の仕組みから何を残し・省き・直したかは [仕分け表.md](仕分け表.md) にあります。

## 部門

| 部門 | すること |
|---|---|
| ①企画部 | ネットで「お金を払ってでも解決したい困りごと」を探し、アプリの案を6つ出して点数を付ける |
| ②市場・競合部 | 似たアプリの値段・弱点・口コミを調べ、勝てるか・伸びるかを判断する |
| ③審査部 | わざと反対の立場から、法律・採算・集客・作れるかを厳しく見る。通れば開発へ |
| ⑤開発部 | アプリを作る（紹介ページ・料金ページ・登録の入口・支払いの練習版まで） |
| ⑥品質部 | 開発部とは別に、実際に動かして検査する。だめなら開発部が自動で直す（2回まで） |
| ⑦公開部 | スマホでも見られる確認用ページを公開する（検索には出ない） |
| ⑧SNS運用部 | 今ある SNS の投稿案を作る。「のぼるの挑戦記」の毎週の投稿も作る |
| ⑨数字・学習 | やめた理由・実際の数字を、次の企画に生かす |
| ⑩物販・アフィリエイト部 | 今の SNS で売れそうな楽天の商品テーマを考え、商品まとめページと PR 付きの投稿案を作る |

SNS の投稿は全部「承認待ち」で今の依頼一覧（`ops/tasks/queue.json`）に入ります。のぼるさんが OK したものだけ、今までどおり ChatGPT が画像・動画にして Metricool で予約します。

## 流れ

```
①企画 → ②市場・競合 → ③審査 → ⑤開発 ⇄ ⑥品質 → ⑦確認用ページ → ⑧SNS案
                                                         ↓
                                  のぼるさんへお知らせ（最終確認.md）
                                                         ↓
                              続ける ／ ブラッシュアップ ／ やめる
```

## はじめにやること（1回だけ）

1. Claude Code の CLI を入れて、今の契約でログインする（各部門はこの契約の中で動くので、追加の料金はかかりません）。
   ```bash
   npm install -g @anthropic-ai/claude-code
   ```
   ```bash
   claude
   ```
2. studio フォルダーで点検する。
   ```bash
   py studio.py doctor
   ```
3. 必要なら `config.json` に書き足す（なくても動きます）。
   - `discord_webhook_url`：お知らせをスマホの Discord で受け取る
   - `signup_url`：事前登録や問い合わせの受け口（Googleフォームなど）
   - `rakuten_app_id`・`rakuten_affiliate_id`：楽天の商品を自動で探してリンクを作る（楽天ウェブサービスで無料登録）

## 使い方

| やりたいこと | コマンド |
|---|---|
| アプリを考えて、最後まで作る | `py studio.py run` |
| 一覧を見る | `py studio.py list` |
| 完成品の資料を見る | `py studio.py show 番号` |
| 続ける | `py studio.py decide 番号 continue` |
| ブラッシュアップ | `py studio.py decide 番号 brushup --note "直す点"` |
| やめる | `py studio.py decide 番号 kill --note "理由"` |
| 挑戦記の今週の投稿案 | `py studio.py sns` |
| 楽天アフィリエイトの企画 | `py studio.py affiliate` |
| 実際の数字を記録 | `py studio.py metrics 番号 --visits 訪問 --signups 登録 --revenue 売上円` |
| 全部まとめて自動で進める | `py studio.py auto` |

`studio.cmd` を使えば `studio run` のようにも書けます。

`auto` は、毎日動かす前提のコマンドです。直しの依頼や作りかけを先に進めます。前回の企画から7日たっていれば、新しく企画します。ただし、のぼるさんの判断待ちが3件以上あるときは、新しく作るのを休みます。SNS と楽天の企画は週1回です。
毎日朝7時に動かすなら、タスク スケジューラに登録します（登録するかは、のぼるさんが決めてから）。
```bash
schtasks /create /tn "事業スタジオ" /tr "C:\場所\venture-agent-sites\studio\studio.cmd auto" /sc daily /st 07:00
```

## Threads 自動投稿（ノボログ）

`threads.py` が、のぼるさんが選んだ投稿だけを、決めた時間に Threads へ出します。

1. 候補を `data/threads_queue.json` に入れる（`py threads.py add 候補.json`）
2. のぼるさんが選ぶ → `py threads.py approve ID 19:00`（`--date` で日付も指定できる）
3. Windows のタスク「NoborogThreadsAutoPost」が10分ごとに `threads.py run` を呼び、時間になった物を投稿する

守ること：承認済みの物だけ出す／1日5本まで／リンクのある投稿は「PR」と「楽天市場」を書く／1本目にリンクを入れない／予定から3時間すぎた物は出さない。
合いことば（アクセストークン）は `secrets/threads_token.txt`（GitHub には上がらない）。7日ごとに自動で延長する。
つながりの確認は `py threads.py check`、公開しない下書きでの確認は `py threads.py test`。

### 翌日の候補を自動で作る（threads_plan.py）

- 毎晩 20:00 にタスク「NoborogThreadsPlan」が `threads_plan.py` を動かし、翌日分の候補10案（各時間2案）を作る。
  - 楽天市場ランキング API（2026年2月以降の新しい窓口 openapi.rakuten.co.jp）から、アフィリエイトリンク付きで商品を取る。
  - 文は `claude -p` が書く。商品の事実は楽天から取った情報だけを渡す。リンクの投稿（PR｜楽天市場…＋リンク＋取得日の価格）はプログラムが付ける。
  - 予定表に「候補」で入り、確認用の一覧 `data/threads_review_MMDD.md` ができる。投稿はしない。
- のぼるさんが選んだ番号を `py threads.py pick 1114-01 1114-03 ...` で承認すると、候補の時間に投稿される。
- 楽天のアプリID・アクセスキー・アフィリエイトIDは `secrets/rakuten.json`（GitHub に上がらない）に置く。
  `rakuten_site_url` は Rakuten Developers のアプリに登録した Web サイトの URL と同じにする。
- `py threads_plan.py --products-only` で、楽天から商品が取れるかだけ確かめられる。

### 写真つきの投稿とプレビュー（threads_preview.py）

- 紹介は人気アカウントと同じ2本のスレッド：1本目＝商品ページの写真4〜8枚（カルーセル）＋短いつかみ、2本目＝「PR｜ひとこと＋▽楽天市場の商品ページ＋リンク＋取得日の価格」。
- 写真は楽天の商品ページの画像を、ショップの並び順のまま使う（文字入れ・切り抜きなどの加工はしない）。
- `py threads_preview.py 1114` で、Threads に出たときの見た目（スレッドの並び・写真・リンクカード・決まりチェック）のページを作る。毎晩の候補づくりでも自動で作られる。

### 動画と写真カード（threads_media.py）

- 紹介の1本目：動画（表紙→楽天の商品写真→終わりの画面、約13秒、1080×1350）＋商品写真のカルーセル。
  楽天の写真には文字を重ねず、切り抜かず、縮小して全体を置くだけ。文字は自分で作った画面にだけ入れる。
- 紹介しない投稿：ノボログの色の写真カード（ランキング／質問／保存用／日記の4つの見た目）。中身は AI が投稿の文から要点を抜き出す。
- 毎晩の候補づくりで自動で作られる。`py threads_media.py make 1117` で作り直せる。
- 公開場所：`media/noborog` ブランチ → https://media-noborog.venture-agent-sites.pages.dev/ （noindex）。
  承認（pick / approve）したときと、投稿の直前に、承認済みの分だけを置く。Threads は投稿時にここから読み込む。
- 必要な物：ffmpeg、Pillow（`py -m pip install --user pillow`）。

### 楽天ROOM との併用（軽く）

- Threads で紹介した商品は、楽天ROOM（room_3a9dcf0b5a）にも載せる。週に数個でよい。
- ROOM の紹介文はこちらで作り、のぼるさんが OK した物だけ載せる。使った体験は書かない。価格は書かない（変わるため）。
- いいね回り・フォロー回りは自動でしない（ROOM の規則に触れるおそれ）。
- 載せ方：のぼるさんの Chrome（楽天にログイン済み）で、商品ページの「ROOMに投稿」の itemcode（`ショップ:番号`）を読み、
  `https://room.rakuten.co.jp/mix?itemcode=ショップ:番号` を開く → コメント欄に文 → 「完了」。
- 2026-11-20 に4つ載せた（チェスト・電気毛布・収納ボックス・加湿器）。
- Threads の投稿のリンクは、楽天の商品ページへ直接のまま（ROOM 経由にしない）。
- 楽天への月のクリックが数百を超えたら、ROOM を本格的にやるか決め直す。

### 投稿のペース（人気の投稿者を調べて決めた）

- 2026-11-22 に、楽天アフィリエイトの人気の投稿者20人の最近の投稿日時を調べた（今動いている10人）。
  - 1日 1〜3回（中央は約2回）。多い人で5回。1回は1〜3本の連投（スレッド）。
  - 時間帯は 朝8〜11時・昼14〜17時・夜19〜22時。いちばん多いのは21時台。
  - リンクは、つかみの後の連投の中に置く人が多い。
  - 外の解説でも「1日1〜2本の質の高い投稿。5本を超えると自分の投稿どうしで食い合う」。
- 決まり（11/22 のぼるさんと決定）：1日3回まで（`threads_max_per_day`）、枠は 10:00・14:00・21:00（`threads_pace_slots`。
  調べた投稿の時間で多かった 朝10時台・昼14時台・夜21時台）、
  ほかの投稿と90分以上・同じ商品は4時間以上あける。OK が多い日は、あふれた分を次の日の空き枠へ自動で流す（`spread_time`）。
- 毎朝6時ごろ、アプリの予定「【毎朝】ノボログの投稿候補づくり」が候補と見本ページを作る（予約・投稿はしない）。

### 売れた商品は「定番」としてくり返す

- 楽天の成果（`data/rakuten_report.json` の注文）に出た商品は、表示や反応の点数にかかわらず、
  `threads_repeat_days_sold`（既定2日）あけて、何度でも候補に戻す（`past_products`）。
- 候補づくりの AI には「毎日1案以上は定番を使い、時刻・型・切り口を毎回変える」と伝える。
- 1件目：2026-11-20 天板つき収納ボックス（フリーライフ・料率10%）。楽天ROOM 経由。

### 動画を作るときの手順（必ず守る）

SNS 用の動画は、次の順番で作る。途中を飛ばさない。1〜4 は見せられる形にしてから次へ進む。

1. 企画書：誰に・何を伝えるか・尺・投稿先・ねらい
2. キャラクターシート：出す人物やキャラの見た目・服・表情を決めて固定する（実在の人・はっきりした顔は出さない）
3. 背景シート：場所・時間帯・色・小物を決めて固定する
4. 絵コンテ：カットごとの画面・動き・秒数・のせる文字
5. 動画作成

### 成績を見て次に活かす（threads_learn.py）

毎日 18:30 に `py threads_learn.py all` が動き（タスク名 NoborogThreadsLearn）、20:00 の候補づくりに結果を渡します。

1. 自分の投稿の成績（Threads API）：投稿ごとの表示・いいね・返信・再投稿・引用・シェアと、楽天リンクのクリック数。
2. 楽天アフィリエイトの成績：日ごとのクリック・売上・成果報酬、ショップ別、注文（専用ブラウザ）。
3. ほかの楽天アフィリエイターの投稿：決めた言葉の検索と見張るアカウントから、反応の数と文の型（専用ブラウザ）。
   言葉は config の `threads_watch_queries`、アカウントは `threads_watch_accounts`。
4. 分析：Claude Code が比べて `data/threads_learnings.md` に「効いたこと・取り入れる型・次に守ること」を書く。
   threads_plan.py はこれをお願い文に入れて、次の候補を作る。ほかの人の文は写さず、型だけ使う。

専用ブラウザ（C:/AI/noborog-browser）は最初に一度 `py threads_learn.py login` で開き、本人が Threads と
楽天アフィリエイトにログインします。ログインが切れたらその部分だけ飛ばし、ログに残します。
