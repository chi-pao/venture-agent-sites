# 以前の仕組みの仕分け表（2026-11-11）

以前の「事業開発AI」（`agent/`。ChatGPT の時代から作ってきたもの）を、新しい「事業スタジオ」（`studio/`）にするときに、何を残し、何を省き、何を直したか。
`agent/` のファイルは消していません（今までの決まりどおり）。新しく事業を作る流れは `studio/` に移ります。

## 残したもの

| もの | 新しい仕組みでの場所 |
|---|---|
| AI は自分で承認しない。最後の判断はのぼるさん | 【最終確認】の `decide`。SNS の投稿も全部「承認待ち」 |
| 出典のない数字を書かない・推測は「仮説」・引用は実際のページから | 全部門の共通の決まり |
| 品質の基準（PC幅とスマホ幅、保存と再読み込み、不正な入力、未完成を完成と書かない） | ⑥品質部 |
| 確認用ページを Cloudflare（venture-agent-sites.pages.dev）で見られる仕組み | ⑦公開部 |
| SNS の流れ（依頼一覧 → のぼるさんの OK → ChatGPT が作る → Metricool で予約） | ⑧SNS運用部・⑩物販部が依頼一覧に「承認待ち」で入れる |
| SNS の決まり（PR 表記・AIで作成の表示・UTM・1日3投稿まで・作った数字禁止） | ⑧⑩の指示書と、`tools/chatgpt_packets.py` の検査 |
| 今あるアカウント（YouTube「のぼるの挑戦記」・note・Instagram・Threads・TikTok） | ⑧⑩が使う先 |
| 却下・中止の理由と実際の数字から学ぶ | ⑨数字・学習（次の企画部に渡す） |

## 省いたもの

| もの | 省いた理由 |
|---|---|
| ローカルAI（Ollama qwen2.5:7b）で企画・設計・コード作成・採点 | 判断と制作の質が足りなかった（33件作って収益0円）。Claude Code に置き換え |
| RSS の見出しだけの市場調査 | 需要の根拠にならない。競合の料金・レビューまで実際に開いて調べる形に |
| 「1つのHTMLだけ・外部APIなし」の縛り | 無料の代わりが多い道具ばかりになり、お金を払う理由が作れなかった |
| 制作AIモデルの比較（ベンチマーク） | Claude Code に任せるので不要 |
| Bluesky・Mastodon へ直接投稿する機能 | 投稿は Metricool に一本化（今の運用） |
| Streamlit の管理画面と 8,200 行の1ファイル | 部門ごとの小さなファイルに分けた。一覧は `data/BOARD.md` |

## 直したもの

| 前の問題 | 直し方 |
|---|---|
| 企画と審査が同じAI（自分の案に甘い） | ①企画部・②市場・競合部・③審査部を別々の担当にし、審査部は反対の立場から見る |
| 集客を作ったあとで考えていた | 企画の時点で「最初の100人への届け方」を採点に入れた |
| 支払いの仕組みがなかった | 開発部が紹介ページ・料金ページ・登録の入口・支払い（Stripe のテストモード）まで作る |
| 確認用ページが main に溜まり続けた（review-previews/） | 案ごとに1つの `preview/` ブランチを上書き。main には入れない |
| 返事が英語になることがあった | 全部門の決まりに「すべて日本語」を入れた |
| AIの出力が崩れると止まった | 形が足りないときは、1回だけ出し直しを頼む |
